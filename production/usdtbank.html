🏗 How Scam SPAs Handle Auth on a Static Website

Step 1 — Static Shell

index.html (Vue/React SPA)

The login page is pure HTML/JS. No server-side auth. Served from cheap cloud storage (Aliyun OSS, AWS S3).

Vue Router · hash mode (#/)
Step 2 — API Call

POST → api.tk-shop.com/login

Form submits username + password to a separate backend API (Node.js / PHP / Python on a hidden server).

Axios · fetch()
Step 3 — Fake JWT

Token stored in localStorage

Server returns a token. Stored client-side. No HttpOnly cookie. Trivially readable by any JS — intentional.

localStorage.setItem('token', jwt)
Step 4 — Account Data

All balances are JSON from API

Balance, tasks, referrals are fetched on load. The server returns any number they want. No real ledger exists.

GET /user/info · Authorization: Bearer
Step 5 — Data Harvest

Real goal: collect your data

Phone number, email, bank/crypto address collected at registration. This is the actual product being sold.

Personal Data → Criminal Networks

Auth Architecture

Password sent in plaintext (often)

Many of these sites send passwords without proper hashing or over HTTP. The backend is a throwaway — security is irrelevant because the site will be shut down and relaunched.

⚠ Passwords reused from other services are immediately useful to attackers.
localStorage Pattern

What happens on submit

The form doesn't POST to a server page — it calls a JavaScript function that fetches the API, gets a token, stores it in localStorage, then uses Vue Router to navigate to #/account.

// On button click (not form submit)
await login(phone, pass)
localStorage.setItem('tk_token', jwt)
this.$router.push('/account')

Session Check

Vue Router navigation guard

On every route change, the SPA checks localStorage for the token. If missing, it redirects to #/login. This is the entire "auth" system — one localStorage key.

router.beforeEach((to, from, next) => {
const token = localStorage.getItem('tk_token')
if (!token) next('/login')
else next()
})

Technical Reality

What's actually in localStorage

Open DevTools → Application → localStorage on any scam site and you'll find exactly these keys. The token is a standard JWT — you can decode it at jwt.io and see the payload is just a user ID and expiry.

⚠ Anyone with XSS access can steal this token and impersonate you.

The Permanent Block

Withdrawal always fails for Level 1

The /withdraw endpoint checks user.level server-side. Level 1 always returns an error regardless of balance. The only way to "upgrade" is to pay real money. After paying, level becomes 2 — but withdrawal now requires a new minimum or fee.

if (user.level < 2) {
return { err: "Upgrade required" }
} else if (balance < 500) {
return { err: "Min $500 to withdraw" }
